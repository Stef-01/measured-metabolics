# Week 5 — Stage 5a (Supabase schema + Auth + RLS)

End of vibe; everything below is production-grade — but only insofar as the
environment provides one. This week wires every artefact (schema, RLS, auth,
audit, permission tests) so a Supabase project URL + anon key is the _only_
thing required to flip from mocks to real backend.

## Build (Mon–Wed)

### Schema

- `supabase/migrations/0001_init.sql` — full ~30-table schema covering identity, patient core, clinical, CGM/meals/symptoms, care coordination, billing, tasks, consent, documents, audit, AI subsystem, integrations.
- Trigger `audit_events_immutable()` blocks UPDATE/DELETE on `audit_events` (PRD §16 audit invariant).
- Cross-table `set_updated_at` trigger applied to every table with `updated_at`.

### RLS

- `supabase/migrations/0002_rls.sql` — every table is `enable + force row level security`, deny-by-default.
- Helper functions: `auth_role()`, `auth_is_admin()`, `auth_has_clinical_access()`, `auth_patient_id()`, `auth_can_see_patient(p uuid)` — the latter encodes PRD §16.3 (patient sees own; dietitian sees assigned; GP sees referred; admin gated by clinical_access JWT claim).
- Policies for all 30 tables; admin-without-clinical-access is **explicitly denied** clinical reads via the helper.

### Auth + clients

- Deps: `@supabase/supabase-js`, `@supabase/ssr`.
- `src/lib/supabase/env.ts` — env probe with `isSupabaseConfigured()` so vibe stages keep running with mocks until real keys are provided.
- `src/lib/supabase/client.ts` — `createBrowserClient<Database>` cached.
- `src/lib/supabase/server.ts` — `createServerClient<Database>` reading `cookies()` (RSC-safe set/no-op).
- `src/lib/supabase/server.ts#supabaseService()` — service-role client for server actions and audit writes.
- `src/middleware.ts` — Next.js proxy that (a) early-exits when env is missing (vibe-mode), (b) gates protected routes, (c) hydrates Supabase session into cookies, (d) **role-based redirect on sign-in** by reading `memberships.role`.
- `src/app/sign-in/page.tsx` — magic-link form; degrades visibly to a "Stage 5a wired; provision Supabase to enable" notice when env is unset.
- `src/app/auth/callback/route.ts` — `exchangeCodeForSession` + `from`-aware redirect.

### Audit helper

- `src/server/audit.ts#recordAudit()` — no-ops in vibe stages, inserts an `audit_events` row when configured.

### Generated types stub

- `src/types/db.ts` — hand-mirrored Database type so the app compiles without the Supabase CLI. Stage 5b replaces with `supabase gen types typescript`.

### Env example

- `.env.example` — every key required Stages 5–9 in one place.
