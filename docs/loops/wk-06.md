# Week 6 — Stage 5b (Storage + data-layer swap + audit deepening + Realtime)

The cutover. From Week 7 onward, every feature lands wired through Supabase
the same day. This week put the cutover plumbing in place so any consumer
can be flipped from mock → Supabase by the presence of `.env.local`.

## Build (Mon–Wed)

### Storage
- `supabase/migrations/0003_storage.sql` — buckets `meal-photos`, `report-pdfs`, `consent-docs` with explicit RLS bucket policies that mirror the Stage 5a row policies (patient writes own folder; clinicians read via `auth_can_see_patient`).
- `src/lib/storage/upload-meal-photo.ts` — one entry point used by every meal-capture surface. Falls back to a `data:` URL in vibe mode so `/p/meal` keeps working unchanged.

### Data-layer swap
- `src/lib/query/provider.tsx` — TanStack Query provider mounted in `src/app/layout.tsx` ahead of `DeviceFrame`. `staleTime: 30s`, no window-focus refetch.
- `src/server/services/index.ts` — service layer covering patients, meals, referrals, symptoms, threads. Each function:
  - Hits Supabase when `isSupabaseConfigured()`.
  - Falls back to the Stage 1–4 mock fixtures otherwise.
  - Mutations call `recordAudit()` with the right `action` enum (`meal.approved`, `referral.created`, etc.).

### Realtime
- `src/lib/realtime/use-meal-queue-channel.ts` — subscribes the dietitian queue to Supabase Realtime on `meal_logs` and `meal_analysis`, invalidating the `["meal-queue"]` query so a second window refreshes within a tick. No-ops when env is unset (vibe mode keeps cross-tab sync via `localStorage`).

### Inngest scaffold
- `src/inngest/client.ts` and `src/app/api/inngest/route.ts` — the project handle and route handler exist; **functions land Week 7**. Stage 6 is now a pure additive change.
