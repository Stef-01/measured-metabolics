## Build (Mon–Wed)

### Admin Console
Seven pages under `/admin/*`:
- `/admin/kpi` — north-star metric (completed metabolic care loop rate).
- `/admin/audit` — filterable append-only log.
- `/admin/organizations`, `/admin/users` — Stage 8 placeholders kept stable.
- `/admin/patients`, `/admin/referrals` — service-layer driven; reads through `listPatients` / `listReferrals` so vibe + Supabase modes both work.
- `/admin/settings` — env flag dashboard (Supabase / PostHog / Sentry / OpenAI / Anthropic / Inngest / pilot flag).
- `src/app/admin/layout.tsx` — sidebar with seven tabs.

### KPI
- `supabase/migrations/0004_kpi.sql` — materialized view `kpi_completed_loops` joining `audit_events` rows for `referral.created` → `meal.uploaded` (≥3) → `meal.approved` (≥1) → `report.sent` → `record.viewed` (target_type `dietitian_report`) within a 4-week window.
- `refresh_kpi_completed_loops()` for nightly refresh (Stage 9: wire to Vercel Cron / pg_cron).
- `/admin/kpi` page renders from materialized view when configured; falls back to a 4-row vibe fixture with a 75% completion rate.

### Telemetry
- `src/lib/analytics/events.ts` — 30 PostHog events centralised (PRD §7.12, §8.13, §9.12). Persona-prefixed names so PostHog grouping is automatic.
- `track()` lazy-imports `posthog-js` and no-ops without `NEXT_PUBLIC_POSTHOG_KEY`.
- Sentry: `src/lib/analytics/sentry.{client,server}.ts` + `/api/sentry-health` returns `{ ok, sentry_dsn_configured, ts }` for the launch checklist's readiness probe.

### Demo seed
- `supabase/migrations/0005_seed_demo.sql` — orgs (Riverbend, Westside, Measured Demo), 5 MBS rules, 5 conditions, 2 recipes. Idempotent (`on conflict do nothing`).
- Patient/user/membership/meals/cgm/symptoms cohort generation deferred to a Stage 9 TS script (`scripts/seed-demo.ts`) since 6 weeks of consistent meal/CGM/audit data needs JS-side UUIDs and timestamp spreading.
