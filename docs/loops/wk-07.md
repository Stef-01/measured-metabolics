# Week 7 — Stage 6 (AI layer + async workers)

The AI layer lands behind a **structured-output-only** door. Patients never
see a draft until a dietitian explicitly approves it; provider failures route
straight to the dietitian queue with `requires_human_review: true` and a
`safety_flags` reason. PRD §15.2 invariants are enforced by code, not by
convention.

## Build (Mon–Wed)

### Schemas (`src/ai/schemas.ts`)
Five Zod schemas with the audit triplet (`confidence_score`, `requires_human_review`, `safety_flags`):
- `MealAnalysisSchema`
- `TranscriptAnalysisSchema`
- `MealPlanDraftSchema`
- `DietitianReportDraftSchema`
- `MessageAssistantSchema`

### Prompts (`src/ai/prompts.ts`)
In-code prompt registry with system prompt, user template (mustache-style `{{var}}`), and explicit `safetyRules`. Stage 8 seeds the same content into `prompt_versions` so versions can evolve without redeploys.

### Provider (`src/ai/provider.ts`)
- `LLMUnconfiguredError` — thrown when neither `OPENAI_API_KEY` nor `ANTHROPIC_API_KEY` is set.
- `runStructured()` — single entrypoint for every worker; uses Vercel AI SDK `generateObject` with the named schema.
- Provider preference order: `preferred` arg → Anthropic → OpenAI → throw.

### Safety gate (`src/ai/safety.ts`)
- `CONFIDENCE_THRESHOLD = 0.7`.
- `applySafety()` enforces:
  - `confidence_score < 0.7` → `requires_human_review = true`
  - `safety_flags` includes `schema_violation` or `provider_unconfigured` → review required
  - `meal-plan-draft` and `dietitian-report-draft` are **always** review-required
  - `visible_to_patient = false` until an explicit dietitian-approval flow flips it (Stage 6 only models the gate; the flip is wired in Stage 7)
- `buildUnreviewedFallback()` — workers call this when the provider is unconfigured or the schema violates so the dietitian queue still gets a row.

### Workers (Inngest)
Five functions wired into `src/app/api/inngest/route.ts`:
- `meal-vision` — trigger `meal.uploaded`. Calls `meal-analysis`, applies safety, audits as `meal.uploaded`.
- `transcript-analyzer` — trigger `transcript.pasted`. Calls `transcript-analysis`, audits as `record.created` (target: transcript).
- `report-draft` — trigger `report.requested`. Calls `dietitian-report-draft`, audits as `report.drafted`.
- `meal-plan-draft` — trigger `meal_plan.requested`. Calls `meal-plan-draft`, audits as `plan.drafted`.
- `notifications` — trigger `notification.dispatch`. Stage 6 logs + audits; Stage 7 wires Resend / Twilio + marketing-consent suppression.

Each worker uses `step.run("call-…")` so retries are scoped per step (PRD §15: "retries 2 with corrective prompt"). Provider/Schema failures are caught and converted into an unreviewed fallback row — the meal still appears in the dietitian queue, never the patient app.

## Loop 2 — End-to-end real-AI dry-run (Sat)
